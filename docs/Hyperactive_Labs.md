## 3. Engineering direction — C-first, not an ISA-backend program

**Author decision U036: C is the chosen compilation target.** A bespoke direct-x86 backend is not the primary implementation path. Building and proving separate direct backends for x86, ARM, and other instruction sets is not near-term work and must not be installed as a prerequisite to the first paper, release, or useful native execution.

The intended route is Hyperactive construction/evaluator/residual → C → an existing C compiler → the selected target. Which constructions are lowered and how their runtime support is represented belong to the implementation; this decision does not impose a new split in the underlying mathematics.

Avik’s stated verification priority is to lift the C compiler and establish its relevant correctness for x86 before undertaking bespoke x86 proof work. This is a future verification/contribution route, not an accomplished result or a new mandatory pre-release gate. His intended open-source phase permits other contributors to take ownership and receive credit for useful implementation work. No license, release date, contributor assignment, or public repository change has been selected here.

**Editorial consequence:** C must not be buried as an optional afterthought while x86-specific construction appears to define the project. The general account of native realization, semantic preservation, and composition of correctness evidence remains pertinent. The choice of a reused C compiler changes the concrete realization path, not the need to identify what each transformation preserves. No particular external C compiler is selected by U036.

**Proof-composition rationale (assistant explanation, not an extra author requirement):** a relation from a represented computation to generated C composes with the chosen C compiler’s source-to-target relation. Initially an external-compiler relation may be explicitly assumed; later verification of the reused compiler can replace that assumption. Architecture-specific semantics reside in the chosen downstream relation rather than requiring every Hyperactive program or the initial implementation to reconstruct an ISA backend. C-first is not a claim that compiler correctness is automatic.
